# Personal Hunk checkout

This branch starts from Hunk v0.23.0 and carries three personal review changes: per-file Smart
layout, session-only Viewed marks, and a fixed column for the Viewed checkbox. Viewed marks belong
to the current review session; viewed files show a checkmark in the Files pane, with an
empty aligned slot for unviewed files. Viewed marks are not written into the repository or user config.

The setup helper builds this checkout into private, versioned releases under .personal/. Its
default command shim lives at .personal/bin/hunk (hunk.cmd on Windows), so it leaves any existing
Hunk command alone. It does not edit shell profiles, the global Git config, or XDG_CONFIG_HOME.

## First setup

Install Git and Node.js 22 or newer with npm, then clone the personal branch:

```sh
git clone --branch personal https://github.com/brettsherwood/hunk.git
cd hunk
node scripts/setup-personal setup
```

The helper reads the exact Bun version from package.json, installs it with npm's local
--prefix under .personal/toolchain, runs bun install --frozen-lockfile with Git-hook
installation skipped, runs typecheck, and builds into a unique .personal/build/ directory. It
stages the binary and its matching skills in an immutable release, checks --version, --help,
both bundled skill paths, and the daemon wire revision, then atomically activates that release.
The daemon probe uses a private temporary runtime directory and an unused loopback port, so it
cannot attach to another Hunk install.

On the first successful setup, the helper backs up an existing user config before changing it and
applies the named top-level values in personal/defaults.toml. Later updates add only missing settings. Use
--apply-defaults to reapply those values, or --skip-config to leave the config alone. Other
keys, tables, and comments remain in place.

If XDG_CONFIG_HOME is set, it must be an absolute path for config defaults to be applied. The
launcher leaves XDG_CONFIG_HOME untouched, so Hunk continues to use the same user config and
installed extensions.

The helper stops if the config file itself is a symlink, since atomic replacement would break the
link; use --skip-config and manage that file manually. It also refuses to replace an existing
hunk command that was not generated by this helper. Choose a separate --install-dir in that case.

## Use the personal build

Add .personal/bin to PATH manually for the current terminal session. For example:

```sh
export PATH="$PWD/.personal/bin:$PATH"
```

PowerShell:

```powershell
$env:Path = "$PWD\.personal\bin;$env:Path"
```

The wrapper selects the active release and sets HUNK_INSTALL_SOURCE=dev, a private
XDG_RUNTIME_DIR, HUNK_MCP_HOST=127.0.0.1, and the persisted per-install HUNK_MCP_PORT. It
does not redirect user config or extension discovery. A rebuild with the same daemon wire revision
reuses the existing namespace; a wire revision change receives a new private runtime directory
and port.

## Update and recover

Pull source changes from the personal branch, then build and activate them:

```sh
git pull --ff-only
node scripts/setup-personal update
node scripts/setup-personal status
node scripts/setup-personal rollback
```

rollback switches to the previous verified release without deleting either release. Older
release directories are kept so an already running process, including one on Windows, can finish
using its binary. --install-dir <path> writes a command shim elsewhere when desired; the
default remains isolated in this checkout. node scripts/setup-personal --dry-run prints the
planned paths without bootstrapping, building, or changing settings.

The helper never pulls source, commits, pushes, configures Git, edits PATH, or installs Bun
globally. If you make commits in this checkout, set your author identity here only, using the
noreply address shown in your GitHub account:

```sh
git config --local user.name "Your GitHub name"
git config --local user.email "YOUR_ID+YOUR_HANDLE@users.noreply.github.com"
```

The .personal/ runtime, toolchain, build, release, and state directories and root artifacts/
are ignored by Git. The portable installer and defaults remain tracked in personal/.
